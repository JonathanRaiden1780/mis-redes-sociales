# SPEC-053 Architecture Evolution

## Session: August 14, 2026

### Initial Vision (Wrong)
The user initially described "sync between machines" — a `GitSyncService` that pushes/pulls to an external repo.

### Correction 1: Global is Internal
> "Debería ser en el mismo repo" — The global vault lives in `.ai/global/` within the project repo, not an external repo.

### Correction 2: Platform Doesn't Execute Tasks
> "Las IA externas ocuparán la plataforma" — The platform prepares context; external AIs (Claude Code, Trae) execute tasks.

### Correction 3: Hermes Generates Templates
> "Hermes en depth lo haga" — `ai init` generates MASTERPROMPT.md using global context; external AIs just read it.

### Correction 4: Obsidian is Not Global
> "Obsidiana es para humanos, YAML para máquinas" — Obsidian for human-readable notes; `.ai/global/` YAML for machine context.

### Correction 5: Multi-Machine Sync
> "5 máquinas con mismo Hermes, mismo token" — Copy Hermes config (.env, auth.json, platforms, skills) during install.

### Correction 6: Security
> "La configuración está protegida/encriptada correcto?" — Encrypt Hermes config with Fernet + PBKDF2 during install.

### Final Architecture

```
Project Repo
├── .ai/
│   ├── MASTERPROMPT.md     ← Generated by ai init (reads global)
│   ├── memory.yaml         ← Local project memory
│   └── global/             ← SHARED BRAIN (travels with project)
│       ├── rules/          ← Team rules
│       ├── skills/         ← Discovered tools
│       ├── patterns/       ← Architecture patterns
│       ├── projects/       ← Team projects
│       └── index.yaml      ← Search index
└── src/

Flow:
1. ai project init → Hermes generates MASTERPROMPT + templates
2. External AI reads MASTERPROMPT → works with full context
3. ai project sync → Hermes reads AI work, updates global
4. git push/pull → global syncs to all machines
```

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| `.ai/global/` not external repo | No configuration, travels with project, works offline |
| Hermes generates templates | Token-efficient, no external AI needed for setup |
| Platform prepares context, doesn't execute | External AIs are more capable; platform is the knowledge base |
| Encrypt Hermes config | Multi-machine security; passphrase during install |
| Command-based sync, not daemon | Lighter, no persistent process, cron-scheduled |
| Obsidian is secondary | For human-readable docs; YAML is for machines |

### Pitfalls Encountered

1. **Hardcoded `changes=0`** in middleware.py — read actual state instead
2. **Deduplication by name only** — use composite key (`name:type`)
3. **Plaintext Hermes config** — encrypt with Fernet + PBKDF2
4. **No preflight checks** — verify Python 3.12+, git, curl, sha256sum, Hermes, Docker, Ollama
5. **Install breaks on missing tools** — auto-install prerequisites
6. **External repo assumption** — global is inside the project

### Security Patterns Applied

- Fernet + PBKDF2 (600k iterations) for credentials
- TOTP 2FA with ±30s clock skew
- `fcntl.flock(LOCK_EX)` for read-modify-write
- `chmod 0o600` on all state writes
- `yaml.safe_load()` only
- URLs validated against git remote helper injection
- Memory overwrite (`key = "x" * len(key)`) not just `del key`
